公式
y = X·w + b + ε
ε ~ N(0, 0.01²) 是噪声项
为什么加噪声？
真实数据永远有测量误差。噪声让模型学到泛化能力，而不是死记标签。

为什么要 shuffle？
避免模型学到数据顺序的规律。每个 epoch 重新打乱，让训练更随机。
Mini-batch 的意义
1000个样本 / 10 = 100次 参数更新/epoch

初始化参数
③
初始化模型参数 & 前向传播
linreg(X, w, b)
# 初始化为接近0的随机值（requires_grad=True 开启自动微分） w = torch.normal(0, 0.001, size=(2,1), requires_grad=True) # 初始 w ≈ [[0.0007], [-0.0003]] b = torch.zeros(1, requires_grad=True) # 初始 b = [0.0] # 前向传播：对当前batch的10个样本做预测 def linreg(X, w, b): return torch.matmul(X, w) + b # (10,2) @ (2,1) + (1,) → (10,1)
前向传播计算过程（第1个batch，第1个样本）
步骤数值说明
输入 x[−0.5211, 1.2034]特征向量
初始 w[[0.0007], [−0.0003]]随机初始化
初始 b[0.0]零初始化
ŷ = Xw+b−0.5211×0.0007 + 1.2034×(−0.0003) + 0 = −0.000725预测值（很差）
真实 y−0.8742标签
第1次预测为什么这么差？
因为 w 初始化为接近 0，b=0，所有预测都约等于 0。损失很大，但梯度信号也很强，这正是训练开始的起点。
矩阵维度
X: (10,2)  ×  w: (2,1)  =  (10,1)
每次得到10个预测值，与labels(10,1)对比。
计算损失
④
计算损失函数
squared_loss(ŷ, y)
def squared_loss(y_hat, y): return (y_hat - y.reshape(y_hat.shape))**2 / 2 # 对batch内所有损失求和，然后反向传播 l = squared_loss(linreg(X, w, b), y) # 形状 (10,1) l.sum().backward() # 自动计算梯度

为什么除以 2？
纯粹是数学上的方便：对 (ŷ−y)² 求导会出现系数 2，除以 2 后导数正好是 (ŷ−y)，公式更整洁。
l.sum().backward()
对所有10个损失求和再反向传播，PyTorch 自动计算 ∂L/∂w 和 ∂L/∂b，结果存入 w.grad 和 b.grad。
反向传播 + 更新
⑤
梯度下降更新参数
sgd([w, b], lr=0.03, batch_size=10)
def sgd(params, lr, batch_size): with torch.no_grad(): for param in params: param -= lr * param.grad / batch_size # 梯度除以batch_size取平均 param.grad.zero_() # 清零梯度，防止累加
第1次参数更新（数值示例）

更新前 w = [[0.0007], [−0.0003]]，b = [0.0]

设 w.grad ≈ [−14.52, 18.73]，b.grad ≈ −7.81

w -= 0.03 × (−14.52) / 10 = w + 0.04356
b -= 0.03 × (−7.81) / 10 = b + 0.02343

更新后 w ≈ [[0.0443], [−0.0593]]，b ≈ [0.0234]
（仅1次迭代，w 已向真实值 [2, −3.4] 方向移动）
为什么要除以 batch_size？
我们用了 l.sum() 而不是 l.mean()，所以梯度是 batch 内所有样本梯度之和。除以 batch_size 换算成平均梯度，使学习率 lr 的含义不随 batch 大小变化。
为什么要 zero_() 清零？
PyTorch 默认累加梯度（多次 backward 梯度叠加）。每次迭代开始前必须清零，否则梯度会越来越大导致训练崩溃。

为什么没有完全收敛到0误差？
数据生成时加了 N(0, 0.01²) 的噪声，模型无法拟合噪声项，最终损失下界约为 0.01²/2 ≈ 0.00005，这正是我们看到的收敛值。
仅3个 epoch 就收敛的原因
这是精心设计的线性问题，lr=0.03 恰当，数据量足够。真实深度学习问题通常需要数十到数百 epoch。
