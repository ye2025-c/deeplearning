# 线性回归简洁实现 — 问答笔记

---

## 简洁实现 vs 从0实现的对应关系

**Q：封装后不太好理解，两个版本有什么差异？**

两个版本做的事完全一样，只是封装层级不同：

| 从0实现 | 简洁实现 | 做的事 |
|---|---|---|
| 手写 `data_iter`（shuffle + 切片 + yield） | `TensorDataset` + `DataLoader` | 批量加载数据 |
| `linreg(X, w, b)` | `nn.Linear(2, 1)` | 线性变换 `Xw + b` |
| `squared_loss` | `nn.MSELoss()` | 均方误差 |
| `sgd(params, lr, batch_size)` | `torch.optim.SGD` + `trainer.step()` | 梯度下降更新参数 |
| `param.grad.zero_()` | `trainer.zero_grad()` | 清空梯度 |

`TensorDataset` 把 `features` 和 `labels` 绑定在一起，保证取数据时下标始终对齐。`DataLoader` 内部干的事和手写 `data_iter` 一模一样：打乱 → 按 batch_size 切片 → yield。

## iter() 函数

**Q：`next(iter(data_iter))` 里的 `iter()` 是什么？**

- **可迭代对象（Iterable）**：能被 `for` 循环遍历，但不能直接调 `next()`。DataLoader 是可迭代对象。
- **迭代器（Iterator）**：在可迭代对象基础上，额外支持 `next()` 手动取下一个元素。

```python
# for 循环内部自动调 iter() + next()，可以直接用：
for X, y in data_iter:
    ...

# 手动取一批数据，需要先转成迭代器：
next(iter(data_iter))
# 直接 next(data_iter) 会报 TypeError
```

从0实现的 `data_iter` 函数用了 `yield`，返回的是生成器（天生是迭代器），可以直接 `next()`，不需要额外套 `iter()`。

## nn.Sequential 和 nn.Linear

**Q：`nn.Sequential(nn.Linear(2, 1))` 是什么？**

`nn` 是 `torch.nn` 模块，PyTorch 的神经网络工具箱。

**`nn.Linear(2, 1)`**：全连接层，等价于手写的 `linreg`：
- `2` → 输入特征数
- `1` → 输出数
- 自动创建并管理 `w`（形状 `[1,2]`）和 `b`（形状 `[1]`）

**`nn.Sequential(...)`**：容器，把多个层按顺序串起来，多层时优势明显：

```python
net = nn.Sequential(
    nn.Linear(2, 64),
    nn.ReLU(),
    nn.Linear(64, 1),
)
```

`net[0]` 用下标访问具体层，所以 `net[0].weight.data` 对应手写的 `w`，`net[0].bias.data` 对应 `b`。

## 反向传播为什么不需要 .sum()

**Q：为什么简洁实现里 `l.backward()` 不需要 `.sum()`？**

因为两个损失函数返回的形状不同：

```python
# 从0实现：返回每个样本的损失，形状 [batch_size, 1]，是向量
def squared_loss(y_hat, y):
    return (y_hat - y.reshape(y_hat.shape))**2 / 2
# backward() 只能作用在标量上，必须先 .sum() 聚合

# 简洁实现：MSELoss 默认 reduction='mean'，内部自动求平均，返回标量
loss = nn.MSELoss()
# 可以直接 .backward()
```

## 评估时为什么不需要 torch.no_grad()

**Q：打印每一步的 loss，为什么不需要 `torch.no_grad()`？**

**两者其实是一样的**，简洁实现省略 `no_grad` 纯粹是 D2L 为了代码简短，不是因为它可以不加。

- 从0实现加了 `no_grad` 是**规范写法**
- 简洁实现省略是**偷懒**，加不加都能跑，只差内存利用率

根本原因：`w`、`b` 有 `requires_grad=True`，涉及它们的运算会自动构建计算图，`no_grad` 阻止建图，节省内存。不加的话计算图建完后等 `l` 被覆盖时自动回收，结果不受影响。

**Q：手动实现不加 `no_grad`，建立计算图会影响梯度计算吗？**

不会。评估在训练循环外面，两个 `l` 是完全独立的张量，各自有各自的计算图，`backward()` 只沿调用它的那个张量的图往回传，不会跨张量污染。

**Q：简洁实现加 `no_grad` 也没事吧？**

对，加了完全没事，结果一样，只是省了一个计算图的内存分配。加了反而是更规范的写法：

```python
with torch.no_grad():
    l = loss(net(features), labels)
    print(f'epoch {epoch + 1}, loss {l:f}')
```

## 计算图的自动回收

**Q：Python 会自动回收计算图吗？**

是的。Python 有引用计数机制，对象没有变量引用时内存自动释放。

- `l.backward()` 默认 `retain_graph=False`，反向传播完成后**主动释放**计算图节点
- 评估时没有调 `backward()`，计算图挂着直到 `l` 被重新赋值或离开作用域才回收

加 `no_grad` 的意义是**根本不构建计算图**，而不是依赖事后回收，数据量大时内存差异才明显。

## 复习总结（2026-05-28）

**Q：简洁实现每个模块对应从0实现的哪个部分？训练循环顺序是什么？**

### 模块对照

| 步骤 | 从0实现 | 简洁实现 |
|------|---------|---------|
| 数据迭代 | 手写随机采样 + yield | `TensorDataset` + `DataLoader` |
| 模型 | 手写 `Xw + b` | `nn.Linear(2, 1)` |
| 损失 | 手写均方误差 | `nn.MSELoss()` |
| 梯度清零 | `w.grad.zero_()` | `trainer.zero_grad()` |
| 参数更新 | 手写 `w -= lr * grad` | `trainer.step()` |

### 训练循环四步，顺序固定

```python
l = loss(net(X), y)   # 1. 前向传播 + 算损失
trainer.zero_grad()   # 2. 清空上一步梯度（必须在 backward 之前）
l.backward()          # 3. 反向传播，算梯度
trainer.step()        # 4. 用梯度更新参数
```

`zero_grad()` 不能放到最后，否则梯度会在下一个 batch 的 backward 时累加，导致更新错误。

### 初始化参数的写法

```python
net[0].weight.data.normal_(0, 0.01)  # 末尾 _ 表示原地操作，直接改 tensor 本身
net[0].bias.data.fill_(0)
```

`net[0]` 用下标取 Sequential 里的第一个层；`.data` 取出原始 tensor（绕过梯度追踪）。
